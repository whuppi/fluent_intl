# fluent_intl — Architecture

How the package is wired. For capability status see [`CAPABILITY_ROADMAP.md`](CAPABILITY_ROADMAP.md); for maintenance recipes see [`UPDATING.md`](UPDATING.md).

fluent_intl is the `package:intl` satellite of the fluent family: the
whole package is the adapter that maps `fluent_bundle`'s ECMA-402
option contract onto `intl`'s `NumberFormat` / `DateFormat` /
`Intl.plural` machinery. The core's architecture (the contract, the
resolver, the conformance harness, the locked satellite template this
package instantiates) lives in
[`fluent_bundle/docs/ARCHITECTURE.md`](../../fluent_bundle/docs/ARCHITECTURE.md)
and is not restated here.

---

## The contract

1. **The whole package is backend-specific.** Every file may speak
   `package:intl` — translating the contract IS the job. Anything
   backend-agnostic sinks to the core.
2. **The ceiling is the intl API, and it is honest.** `package:intl`
   exposes no signDisplay, no rounding modes, no numbering systems, no
   calendars, no time zones. Every one of those options degrades loud —
   `FluentTypeError.unsupportedOption` recorded per call, nearest
   supported rendering returned. The ✗ set is declared in
   `test/conformance_test.dart` and proven both ways by the shared
   harness. No option is silently dropped.
3. **Zero engine setup.** No init, no downloads, no WASM — the CLDR
   data is compiled into `package:intl`. This is the lightweight member
   of the family; icu_kit fidelity is what the icu satellite is for.
4. **Every construction-affecting option is in every cache key.** intl
   formatters are pattern objects built per option bag; the memoizer
   key must carry every field the builder consumes.

## 1. The number pipeline

```
FluentNumber (value + options)
  ↓ number_map.dart — the router
  ├─ per-call DEGRADES for everything above intl's API ceiling:
  │    signDisplay, roundingMode/Priority/Increment, trailingZeroDisplay,
  │    numberingSystem, grouping strategies, useGrouping:false on
  │    compact/currency… — each records unsupportedOption, then the
  │    nearest supported form renders
  ├─ notation folds: engineering → scientific (intl has only the plain
  │    #E0 scientific pattern); scientific with a non-decimal style
  │    degrades to that style's plain form
  ├─ resolveDigits (core) → the ECMA digit bounds
  └─ builder.dart
       buildFormatter: style/notation → the NumberFormat constructor
         (decimal / percentPattern / currency / compact*, l10n name path
         via currency_name.dart)
       applyDigitKnobs: bounds → minimum/maximumFractionDigits +
         significant-digit setters
       optsKey: the memoizer key — EVERY field buildFormatter or
         applyDigitKnobs reads joins the key
```

Notes the code can't show at a glance:

- **Percent auto-scales ×100** in intl's `percentPattern` — matching
  ECMA and the icu satellite, no manual scaling here.
- **`currencyDisplay: name`** does not exist in intl's NumberFormat;
  `currency_name.dart` composes the formatted number with
  `l10n_currencies`' localized display names instead.
- **Scientific is real but coarse** — intl's `scientificPattern` is a
  bare `#E0`. The family matrix marks it ✓ with a fidelity note; icu
  marks it ✗ (no data at all). Different ceilings, both honest.

## 2. The datetime pipeline

```
FluentDateTime (value + options)
  ↓ datetime_map.dart
  ├─ per-call DEGRADES: calendar, timeZone, numberingSystem — intl has
  │    no API for any of them
  ├─ hourCycle / hour12 normalize onto intl's hour machinery:
  │    h11/h12 → the j/jm/jms skeletons, h23/h24 → H/Hm/Hms (intl can't
  │    distinguish within a family, so h11/h24 also record a degrade)
  ├─ dateStyle/timeStyle → named skeleton factories (yMd, yMMMd,
  │    yMMMMEEEEd…) + add_jm/add_Hms for the time side
  └─ field bags → smallest covering factory + add_* composition
       (add_E/add_EEEE for weekday, add_j/add_m/add_s for time fields;
       fields without an add_* method build a supplemental pattern)
```

The load-bearing subtlety: **combined formatters are composed with
`add_*`, never by concatenating skeleton strings.**
`intl.DateFormat('yMd jm')` treats the argument as one literal pattern,
not a composed skeleton — the output is wrong in locales that reorder
date and time. The `add_*` family composes correctly.

## 3. Plurals

`IntlBackend.pluralCategory` → `plural/plural_map.dart`, consuming the
DIGIT STRING from the core's `resolveDigits()` (so visible fraction
digits and rounding options drive selection, same as icu):

- **Cardinal** (`cardinal.dart`): `Intl.pluralLogic` — every locale
  intl ships rules for.
- **Ordinal** (`ordinal.dart`): intl ships NO ordinal rules, so the 42
  CLDR locales with non-trivial ordinal rules are inlined by hand (all
  other locales are `other`-only). The inlined rules are held to CLDR
  by `test/plural/ordinal_cldr_compliance_test.dart` against an
  autogenerated fixture — zero unsupported non-trivial locales, zero
  orphans. Regeneration recipe: [`UPDATING.md`](UPDATING.md) §3.

## 4. The cache

`common/cache.dart`'s `IntlMemoizer` is the formatter cache class —
each pipeline (number, datetime) owns its own instance. Keys come from
`builder.dart`'s `optsKey` (numbers) and the datetime
map's equivalent — locale + every construction-affecting field.
Per-call work (digit knobs are cheap setters on intl formatters, so
they ARE part of construction here — unlike icu, where shaping is
per-call) means the knob fields join the key too. When in doubt: if
two option bags could produce different output, their keys must differ.

## Where to look when X happens

| Symptom | First place to look |
|---|---|
| An option renders on icu but degrades here | The family matrix in the core's CAPABILITY_ROADMAP — intl's API ceiling is lower by design; the degrade error names the option. |
| Two option bags render identically when they shouldn't | `builder.dart` `optsKey` — a construction field is missing from the key. Add it + a row in `number_map_cache_test.dart`. |
| A combined date+time renders in the wrong order for a locale | `datetime_map.dart` — someone concatenated skeleton strings instead of composing with `add_*`. |
| An ordinal is wrong in some locale | `plural/ordinal.dart` — run the compliance test; if CLDR moved, regenerate the fixture (UPDATING §3). |
| A currency long-name is missing/wrong | `number/currency_name.dart` + the `l10n_currencies` dep version. |
| Formatting throws | It must never — intl formatter setters can throw on out-of-range values; the resolved bounds from `resolveDigits` are what keep them in range. |

## The one-line summary

> **One whole-package adapter: option contract in, package:intl out.
> Router → builder → memoizer for numbers; skeleton factories + add_*
> composition for datetimes; Intl.pluralLogic cardinals + 42 inlined
> CLDR-proven ordinal locales. Everything above intl's API ceiling
> degrades loud per call. Zero setup, compiled-in CLDR — the
> lightweight family member, honest about its ceiling.**
